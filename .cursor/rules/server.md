# server 模块规范

## 1. 模块职责

`server/` 是仓库中相对独立的 EdgeReader 后端服务模块，当前关注智能阅读辅助系统的数据库模型、认知标签、向量嵌入与性能基线。它不是 Project Harmony Godot 游戏运行时的一部分，修改时不得把游戏逻辑和服务端逻辑混淆。

| 子域 | 代表路径 | 职责 |
|---|---|---|
| 应用入口 | `server/cmd/` | 后端服务启动入口。 |
| 数据库连接 | `server/internal/database/` | MySQL 连接、配置与初始化。 |
| 模型层 | `server/internal/models/` | 用户、文章、阅读会话、认知标签、向量嵌入等 GORM 模型。 |
| AI 嵌入 | `server/internal/ai/embedding/` | 向量存储接口、MySQL 向量实现、未来迁移抽象。 |
| 知识图谱 | `server/internal/ai/graph/` | 标签关系与邻接结构。 |
| 数据库迁移 | `server/migrations/` | MySQL 表结构、索引与兼容性变更。 |
| 性能文档 | `server/docs/` | 数据库性能基线和查询优化记录。 |

## 2. 数据与迁移契约

服务端使用 Go、GORM 与 MySQL 8.0。迁移脚本必须保持向前可执行、幂等性可审查、字段默认值清晰。认知标签扩展与向量检索模型强调向下兼容，新增字段应提供默认值或可空策略，避免破坏已有查询。

| 修改类型 | 必做检查 |
|---|---|
| 新增表 | 新增迁移文件，补充 GORM 模型，更新 `server/README.md`。 |
| 新增字段 | 检查默认值、索引、旧查询兼容性和 JSON 标签。 |
| 修改索引 | 更新性能基线或说明索引变更目的。 |
| 修改向量模型 | 核对维度、范数、相似度计算、Qdrant 迁移字段。 |
| 修改标签关系 | 核对 `tag_relations`、维度枚举、来源类型和图谱邻接逻辑。 |

## 3. 编辑规则

服务端规则优先保护数据库兼容性和模型一致性。修改模型时，应同步检查对应迁移；修改迁移时，应同步检查模型结构和 README。不要在迁移脚本中写入真实连接信息、测试账号密码或生产数据。

## 4. 与 Godot 项目的边界

`server/` 的 EdgeReader 主题与 Project Harmony 游戏运行时没有直接耦合。除非用户明确提出跨系统集成，不应把 `server/` 的数据库模型、认知标签或向量检索引入 Godot 游戏逻辑，也不应把 Godot 玩法状态写入该服务端模块。

## 5. 禁止行为

不得重排历史迁移编号。不得删除已发布迁移。不得修改旧迁移来表达新需求；应新增迁移。不得把向量字段维度、实体类型和内容哈希逻辑分散硬编码。不得在未说明兼容策略的情况下修改枚举值或索引名称。
