# knowledge-base 模块规范

## 1. 模块职责

`docs/knowledge-base/` 是项目技术知识库，用于沉淀已经验证的 Bug 模式、调试经验、平台坑、性能问题和跨模块排错路径。该目录强调可复用经验，不应成为普通任务日志或临时想法堆放区。

| 内容类型 | 推荐写法 | 使用场景 |
|---|---|---|
| 已知坑 | 触发条件、症状、根因、修复方式、验证方法 | 避免重复踩坑。 |
| Bug 模式 | 关联模块、典型堆栈、复现步骤、排查路径 | 支持快速定位。 |
| 性能经验 | 测试条件、指标、瓶颈、优化策略 | 支持回归和调参。 |
| 工具经验 | 命令、输入输出、失败处理 | 支持 Agent 可复现执行。 |

## 2. 索引规则

新增知识条目时，应同步更新 `docs/knowledge-base/INDEX.md`。标题应可搜索，正文应包含适用范围和反例，避免只记录结论而不记录触发条件。

## 3. 与流程洞察的区别

知识库记录项目技术事实与排错经验；`.cursor/rules/process_insights/` 记录 Agent 协作流程中的非直观步骤、隐性依赖和操作策略。若一个问题既包含技术坑又包含流程坑，可以两处分别沉淀并互相链接。

## 4. 禁止行为

不得把临时任务过程完整转存为知识库。不得写入未经验证的猜测作为结论。不得记录真实凭证、个人信息或不可公开的环境细节。不得新增条目而不更新索引。
