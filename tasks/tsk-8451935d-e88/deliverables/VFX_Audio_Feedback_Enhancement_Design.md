# Project Harmony 视听反馈增强设计方案 (VFX & Audio Feedback Enhancement)

**文档状态：** 最终交付物
**设计角色：** vfx_audio_designer
**日期：** 2026-03-01

## 1. 概述

本方案旨在解决《Project Harmony》教学引导与交互设计评估中指出的两大核心问题：第一，疲劳危机反馈不足，导致玩家在疲劳值达到 CRITICAL 级别时极易忽略屏幕边缘的恢复建议；第二，频谱切换感知薄弱，频谱相位切换（Z/X/C）缺乏足够的视听反馈，导致玩家难以明确感知“世界状态”的改变。

本方案通过构建涵盖视觉、听觉和触觉的多感官反馈系统，旨在全面提升核心机制的可读性，从而增强玩家的心流体验与战斗沉浸感。

---

## 2. Part A: 疲劳危机多感官反馈系统设计

听感疲劳系统（Aesthetic Fatigue Engine）是游戏的核心机制之一。当疲劳值（AFI）累积到不同阈值时，系统必须触发对应层级的多感官警告，确保玩家在激烈的弹幕战斗中也能清晰感知自身状态。

### 2.1 视觉警告分级设计

视觉反馈根据疲劳等级（`MusicData.FatigueLevel`）逐步升级，从轻微的边缘提示平滑过渡到全屏的故障艺术干扰。我们引入了全新的 DANGER 级别以应对极度疲劳状态。

| 疲劳等级 | AFI 阈值 | 视觉反馈表现 | 技术实现方案 |
| :--- | :---: | :--- | :--- |
| **MILD** | 0.3 | **边缘轻微脉冲**：屏幕四周出现微弱的红色呼吸光晕。 | 修改 `hit_feedback.gdshader`，增加基于 `afi_value` 的边缘发光强度参数，脉冲频率设为低频（如 0.5Hz）。 |
| **MODERATE** | 0.5 | **暗角加深与轻微抖动**：边缘红光加深，屏幕发生轻微的高频像素抖动。 | 在 `fatigue_filter.gdshader` 中引入色差（Chromatic Aberration）效果，其强度随 AFI 动态插值。 |
| **SEVERE** | 0.7 | **强烈脉冲与色彩偏移**：屏幕四周红光变为高频闪烁（如 2Hz），整体画面饱和度开始下降。 | 结合 `hit_feedback_manager.gd`，增加周期性的轻微 Camera 抖动；同时在 Shader 中降低 `saturation` 属性。 |
| **CRITICAL** | 0.85 | **中央光晕与严重失色**：屏幕中央出现强烈的脉冲红色光晕（聚焦玩家视线），画面饱和度降至 30% 以下，边缘出现明显的数字故障（Glitch）条纹。 | 引入新的全屏 Shader（如 `critical_fatigue.gdshader`），结合径向渐变遮罩在屏幕中央生成警告光晕，叠加高强度的噪点和扫描线错位。 |
| **DANGER** | > 0.95 | **全屏故障与空间扭曲**：画面出现严重的撕裂、持续的色块偏移，背景发生空间扭曲。 | 触发最高级别的全屏后期处理，大幅增加 `glitch_strength`，同时引入类似 CRT 显示器失去同步的画面跳动效果。 |

### 2.2 音频警告设计

音频反馈需要与游戏“噪音 vs 和谐”的设计哲学紧密契合。由于疲劳代表着“不和谐”的累积，警告音效应以不协和音程、心跳加速和数字噪音为核心元素。

在 **MILD** 和 **MODERATE** 阶段，系统旨在营造一种潜意识的压迫感。具体实现为在背景音乐中混入低频的、缓慢的心跳声（如 60 BPM 的低音鼓）。随着 AFI 的上升，心跳声的音量和频率将逐渐增加。进入 **SEVERE** 阶段后，警告变得明显，心跳声加速至 100 BPM 以上。此时，当玩家施放法术时，原本和谐的合成器音效中会随机混入轻微的失谐（Detune）或位元破碎（Bitcrush）效果。

当疲劳值达到 **CRITICAL** 级别时，危机临近，系统将触发刺耳的警报。专属的警告音效（如高频的、带有失真的合成器警报音）将被播放。同时，通过 `audio_manager.gd` 动态压低主音乐总线（Music Bus）的音量，从而突出警报声和敌人的噪音。若玩家进入 **DANGER** 状态，系统崩溃的听感将被激活。此时会产生强烈的音频故障效果，主音乐发生卡顿、音高下掉（Tape Stop 效果），并伴随刺耳的静电噪音（Static Noise）。

### 2.3 触觉反馈设计

对于使用手柄的玩家，触觉反馈是传达紧急状态的直接且有效的途径。我们将根据疲劳等级设计渐进式的震动模式（Rumble Patterns）。

| 疲劳等级 | 触觉反馈模式 | 设计意图 |
| :--- | :--- | :--- |
| **MILD** | 无震动或跨越阈值时触发极轻微的单次短震动。 | 仅作状态改变的微弱提示。 |
| **MODERATE** | 跨越阈值时触发两次短促震动（低频马达 0.2 秒，强度 30%）。 | 引起玩家初步注意。 |
| **SEVERE** | 伴随音频的“心跳”节奏，产生同步的低频脉冲震动（强度 50%）。 | 强化压迫感与紧张节奏。 |
| **CRITICAL** | 持续的高频微震（高频马达，强度 40%）。 | 模拟系统过载与极度紧张的颤抖感。 |
| **DANGER** | 强烈且不规则的混合震动（高低频马达交替，强度 80%-100%）。 | 配合全屏故障视觉效果，传达最高级别的危险信号。 |

## 3. Part B: 频谱切换视听反馈设计

频谱相位（全频/高通/低通）是《Project Harmony》中控制战斗节奏和应对不同敌人的关键机制。切换频谱相当于切换了“世界状态”，必须提供强烈的、全局性的反馈，以确保玩家明确感知。

### 3.1 全局音频滤波效果

在 `audio_manager.gd` 和音频总线（AudioBus）中，我们将实现与频谱相位直接绑定的全局滤波效果。为了确保听感的平滑性，在切换相位时，滤波器参数将在 0.3 秒内进行平滑插值（Lerp），创造出“潜入水下”或“冲出水面”的自然听觉错觉。

| 频谱相位 | 音效处理 | 参数配置 | 听感特征 |
| :--- | :--- | :--- | :--- |
| **全频 (Fundamental)** | 原始音效，无额外滤波。 | 旁通（Bypass）所有全局滤波器。 | 所有频率的声音均清晰可辨，呈现最自然的游戏环境音。 |
| **高通 (Overtone)** | 启用全局高通滤波器（High-Pass Filter）。 | 截止频率设为约 1500Hz，增加少许共振（Resonance）。 | 低音消失，声音变得尖锐、空灵、具有穿透力，凸显高频的弹体碰撞和碎裂声。 |
| **低通 (Sub-Bass)** | 启用全局低通滤波器（Low-Pass Filter）。 | 截止频率设为约 800Hz，增加一定的驱动（Drive/Saturation）。 | 高音被切断，声音变得沉闷、厚重、有压迫感，凸显重低音的轰鸣和沉重的打击感。 |

### 3.2 视觉过渡特效

我们将扩展现有的 `spectral_phase.gdshader` 和 `phase_transition.gdshader`，在切换瞬间增加极具冲击力的视觉过渡效果。

当玩家从全频切换至 **高通 (Overtone)** 时，屏幕底部将向上快速扫过一道明亮的青蓝色光带（扫描线），扫描线经过的区域画面瞬间变为冷色调。同时，屏幕会出现短暂的向外膨胀的径向模糊（Radial Blur），以模拟能量的释放。

当玩家从全频切换至 **低通 (Sub-Bass)** 时，屏幕顶部将向下重重压下一道暗红或紫色的波纹。随着扫描线的推进，画面整体变暗且对比度增强。瞬间特效表现为强烈的色差偏移（Chromatic Aberration）和轻微的下沉感抖动，有效模拟重力增加的视觉感受。

当玩家从高通或低通恢复至 **全频 (Fundamental)** 时，过渡动画表现为从屏幕中心向四周扩散出一圈白色的能量涟漪。色彩瞬间恢复正常，并伴随一次轻微的白屏闪光（透明度从 0.3 迅速降至 0）。

### 3.3 UI 指示器动画

为了确保玩家即使在视线未聚焦于主角时，也能通过周边 UI 动画感知相位的切换，我们需要强化 UI 的动态反馈。

首先，屏幕角落的相位状态图标在切换时应播放明显的放大缩小动画（Scale Bounce），并伴随高光扫过（Shine Effect）的特效。其次，如果 UI 界面中存在类似五度圈罗盘的元素，切换相位时罗盘应发生快速旋转或齿轮咬合的机械动画，并配以清脆的“咔哒”声效。最后，主角的血条、能量条或施法准星的颜色应随相位发生映射改变。例如，全频状态下使用白色或金色，高通状态下变为青色，低通状态下变为紫色，从而为玩家提供持续的视觉锚点。

## 4. 实施与集成建议

在架构集成方面，视觉反馈逻辑应整合入 `hit_feedback_manager.gd` 和专门的后期处理节点（PostProcessingEnvironment），而音频反馈逻辑则需紧密整合入 `audio_manager.gd` 和 `fatigue_manager.gd`。

在性能优化方面，鉴于全屏 Shader（特别是带有噪点和色差的复杂 Shader）开销较大，强烈建议为低配硬件提供图形降级选项。在低画质模式下，可将全屏扭曲降级为简单的颜色叠加或边缘光晕，以保证帧率稳定。

在无障碍设计（Accessibility）方面，必须考虑特殊玩家群体的需求。对于光敏性癫痫患者，系统应提供“降低闪烁（Reduce Flashing）”选项，将高频脉冲转换为平滑的呼吸灯效果，并完全关闭全屏白闪。对于色盲玩家，需确保相位切换不仅依赖颜色区分（如红与蓝），还必须伴随明确的形状变化或纹理差异（例如高通应用网格纹理，低通应用波浪纹理）。
