## 1. 引言

在《Project Harmony》中，法术特效是动态生成的，由基础音符、音色、修饰符、节奏型和和弦等多个层级组合而成。本文档旨在定义这七大效果层级之间的叠加、混合、冲突解决规则，以及在2.5D渲染桥架构下的性能预算和视觉降级策略，确保在复杂的战斗场景中保持高可读性、强节奏感和稳定的帧率。

## 2. 七层特效组合矩阵

法术特效分为七个层级，从底层环境到顶层全局效果。以下矩阵定义了每层特效如何与其他层叠加。

### 2.1. 层级定义回顾

*   **层级0：全局环境** (章节主题、地面Shader)
*   **层级1：修饰符** (黑键，一次性附加效果)
*   **层级1.5：基础弹体** (音符，决定物理属性和基础形态)
*   **层级2：和弦法术** (形态质变，引入新视觉语言)
*   **层级3：音色** (攻击质感，材质滤镜)
*   **层级4：节奏型** (行为模式，发射轨迹和频率)
*   **层级5：和弦进行** (组合效果，全屏反馈)
*   **层级6：环境与惩罚** (疲劳、单音寂静)
*   **层级7：频谱相位** (共鸣切割，全局重塑)

### 2.2. 组合叠加规则

| 基础层 | 叠加层 | 叠加方式 | 视觉表现规则 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| **层级1.5 (基础弹体)** | **层级1 (修饰符)** | **附加 (Additive/Attachment)** | 修饰符特效作为子节点或额外Shader Pass附加在基础弹体上，不改变基础形态。 | E音符(巨型缓行) + 穿透(C#) = 巨大的能量球前端带有一道锐利的青色激光指示器。 |
| **层级1.5 (基础弹体)** | **层级3 (音色)** | **混合 (Blend/Material Override)** | 音色作为材质滤镜修改基础弹体的Shader参数（如纹理、边缘柔和度），并替换命中粒子。 | G音符(高伤快消) + 弹拨系 = 细小的能量奇点外包裹水墨波纹，命中产生同心圆冲击波。 |
| **层级1.5 (基础弹体)** | **层级2 (和弦法术)** | **替换/质变 (Replacement/Morph)** | 和弦法术的视觉语言具有最高优先级，**完全替换**或**深度重塑**基础弹体的形态。基础音符的属性仅保留在大小和颜色基调上。 | 任何音符 + 减七和弦(天降打击) = 弹体发射被取消，替换为目标区域的血红色预警法阵和天降光柱。 |
| **层级2 (和弦法术)** | **层级3 (音色)** | **附加/混合 (Additive Blend)** | 在和弦法术的专属视觉基础上，叠加音色的标志性元素。 | 爆炸弹体(增三) + 琵琶(弹拨系) = 爆炸变为两次，第二次是金色的光珠爆发。 |
| **层级1.5/2 (弹体/和弦)** | **层级4 (节奏型)** | **行为修改 (Behavioral Mod)** | 不改变弹体本身的材质和粒子，仅改变其发射频率、大小缩放和运动轨迹。 | 强化弹体(大三) + 三连发 = 同时射出三枚较小的金色六边形网格弹体。 |
| **所有法术层 (1-4)** | **层级6 (惩罚)** | **全局覆盖 (Global Override)** | 惩罚效果（如单音寂静的灰色、噪音过载的像素化）具有绝对视觉优先级，强制覆盖底层颜色和材质。 | 任何法术 + 单音寂静 = 弹体瞬间变为灰色，失去所有发光(Emission)效果，并伴随故障粒子消散。 |
| **所有层级 (0-6)** | **层级7 (频谱相位)** | **后处理重塑 (Post-Process Remap)** | 通过全屏Shader和WorldEnvironment参数，对整个画面的色调、对比度和边缘进行重塑。 | 切换至高通 = 全屏线框化、冷色调，所有弹体变亮变细，拖尾变锐利。 |

## 3. 混合模式与Shader叠加规则

在2.5D渲染桥架构下，所有3D特效最终通过`SubViewport`叠加到2D画面上。

### 3.1. 颜色混合规则 (Color Blending)

*   **基础弹体与音色：** 使用 **Alpha Blend** (透明度混合) 保持弹体的实体感，同时通过Shader的 `ALBEDO` 和 `EMISSION` 通道叠加音色纹理。
*   **修饰符与高能爆发：** 使用 **Additive** (加底混合) 增强亮度。例如穿透修饰符的激光、爆炸的中心高光。注意控制Additive层的面积，避免过曝。
*   **惩罚与负面状态：** 使用 **Multiply** (正片叠底) 或自定义的去饱和Shader。例如“单音寂静”会将弹体颜色乘以灰色，降低其视觉权重。

### 3.2. Shader参数叠加方式

法术的最终Shader材质由一个统一的 `SpellMaterial3D` 控制，通过传递 `INSTANCE_CUSTOM_DATA` 来实现批量渲染下的个体差异：

1.  **Base Color (基础色)：** 由层级1.5（音符）决定。
2.  **Emission Multiplier (发光强度)：** 由层级1.5的DMG属性决定，受层级4（节奏型，如精准蓄力）动态放大。
3.  **Texture Mask (纹理遮罩)：** 由层级3（音色）决定（如水墨、丝线）。
4.  **Distortion/Glitch (扭曲/故障)：** 默认值为0，受层级6（惩罚）控制，当触发噪音过载时增加该值。

## 4. 特效优先级排序系统

当多种特效在同一时间、同一实体上触发时，必须遵循严格的优先级解决冲突，以控制视觉噪声。

**优先级排序（从高到低）：**

1.  **P0 - 机制阻断层：** 层级6（单音寂静、不和谐腐蚀）。如果法术被禁用或惩罚，立即清除所有其他特效，仅播放惩罚视觉。
2.  **P1 - 全局重塑层：** 层级7（频谱相位切换）、层级5（和弦进行全屏反馈）。这些效果改变整个屏幕的渲染管线。
3.  **P2 - 形态质变层：** 层级2（和弦法术）。决定法术的根本表现形式（如天降打击优先于普通弹体发射）。
4.  **P3 - 行为与修饰层：** 层级4（节奏型）决定轨迹，层级1（修饰符）附加关键战术信息。
5.  **P4 - 质感与基础层：** 层级3（音色）和层级1.5（基础弹体）。

**冲突解决策略示例：**
*   **冲突：** 玩家同时触发了“精准蓄力（休止符放大）”和“单音寂静（禁用）”。
*   **解决：** P0（单音寂静） > P3（精准蓄力）。蓄力特效立即中断，法术槽变灰，播放卡壳音效。

## 5. 性能预算与视觉降级策略

在2.5D渲染桥架构中，3D渲染（特别是`SubViewport`和粒子）是性能开销的大头。必须制定严格的预算和降级策略。

### 5.1. 性能预算分配 (目标：1080p @ 60FPS)

*   **同屏最大粒子数 (GPUParticles3D)：** 
    *   高端设备：50,000
    *   中端设备：20,000
    *   低端设备：5,000
*   **Shader Pass 上限：** 
    *   每个法术实体最多 2 个 Pass (Base + Outline/Glow)。
    *   全屏后处理最多 3 个 (Glow, Tonemap, 疲劳/相位滤镜)。
*   **DrawCall 预算：** 
    *   3D渲染桥内控制在 100 以内。重度依赖 `MultiMeshInstance3D` 进行弹体批处理。

### 5.2. 视觉降级策略 (LOD)

基于设备的性能压力或游戏内的“听感疲劳”状态，系统将自动触发视觉降级：

| 降级级别 | 触发条件 | 降级措施 |
| :--- | :--- | :--- |
| **LOD 0 (完整)** | 性能良好，疲劳度低 | 开启所有粒子、长拖尾、高质量Glow、全屏扭曲效果。 |
| **LOD 1 (简化)** | 帧率波动，或疲劳度中等 | 1. 粒子发射率减半。<br>2. 拖尾长度缩短30%。<br>3. 关闭次要环境特效（如层级0的浮动几何体）。 |
| **LOD 2 (核心)** | 性能吃紧，或疲劳度极高 | 1. 禁用所有非关键粒子（保留命中和爆炸）。<br>2. 拖尾替换为简单的线条Shader。<br>3. 降低Glow的分辨率和迭代次数。<br>4. 视觉表现向“数字衰变”靠拢，利用色块和低多边形替代复杂特效。 |

## 6. 特效池化与复用策略

为了减少实例化开销，避免战斗中的卡顿，所有特效必须接入现有的 `ObjectPool` 基础设施。

### 6.1. GPUParticles3D 预热与池化

1.  **预热编译：** 在场景加载时，将所有可能用到的粒子系统（如爆炸、命中、法阵）在屏幕外发射一次，强制编译Shader并缓存材质。这能有效避免首次施法时的卡顿。
2.  **统一特效管理器 (`VFXManager3D`)：** 
    *   维护一个按特效类型分类的对象池（如 `hit_sparks_pool`, `explosion_pool`）。
    *   当需要播放命中特效时，从池中获取一个 `GPUParticles3D` 节点，设置位置和颜色，触发 `emit`。
    *   利用粒子的 `finished` 信号，在发射结束后自动将其归还到对象池。

### 6.2. MultiMesh 动态扩容

基础弹体不使用独立节点，而是统一由 `ProjectileManager3D` 的 `MultiMeshInstance3D` 渲染。

1.  **批量渲染：** 所有的基础弹体共享同一个Mesh和Material，仅通过 `INSTANCE_CUSTOM_DATA` 传递位置、旋转、颜色和音色参数。
2.  **弹性扩容：** 当弹体数量超过当前 `MultiMesh` 容量时，按块（如每次增加100）进行弹性扩容，而非逐个增加，以减少内存重新分配的开销。

### 6.3. 材质参数动画 (Tween)

对于需要动态变化的特效（如法阵的展开、弹体的消散），避免在 `_process` 中逐帧修改材质参数。应使用 Godot 4.x 高效的 `Tween` 系统来插值 Shader 参数，这比在 GDScript 中计算要高效得多。

## 7. 总结

本方案为《Project Harmony》的法术特效系统建立了一套严密的组合规则和性能管理机制。通过明确七大层级的叠加方式、制定严格的优先级解决冲突，并配合2.5D渲染桥架构下的性能预算与池化策略，我们能够在保证游戏“通感”美学和视觉冲击力的同时，确保在各种设备上都能提供流畅的战斗体验。
