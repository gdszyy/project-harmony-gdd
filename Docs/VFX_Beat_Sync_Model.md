## 1. 引言与设计目标

### 1.1. 背景问题

《Project Harmony》现有的 `Spell_Visual_Enhancement_Design.md` 详细描述了各类法术的静态视觉形态（颜色、粒子、质感），但完全缺少**时间轴上的节奏编排**。在节拍同步战斗中，特效的每个阶段（预兆/释放/持续/命中/消散）应该精确对齐到BPM的哪个位置，这一核心问题至今没有定义。

《Hi-Fi Rush》等游戏已经证明，将整个世界的动画（包括特效、UI、环境）严格绑定到音乐BPM上，能够产生无与伦比的沉浸感和打击感。对于《Project Harmony》这样一款"战斗即创作"的游戏，特效的节拍同步不是锦上添花，而是核心体验的基石。

### 1.2. 设计目标

本文档旨在建立一套完整的、可执行的**特效生命周期节拍同步模型**，覆盖以下核心内容：

1. 定义游戏中所有特效时间轴的基础时间单位和信号接口。
2. 为基础弹体（自动施法/手动施法）设计精确的发射-飞行-命中-消散节奏模型。
3. 为9种和弦法术形态设计蓄力-释放-持续-结束节奏模型。
4. 为5种黑键修饰符设计激活-附着-触发节奏模型。
5. 定义6种节奏型对弹体发射时序的影响。
6. 为3种和弦进行组合效果设计触发-爆发-消散节奏。
7. 设计"节拍量化"机制，处理特效触发时机与节拍不完全对齐的情况。
8. 定义疲劳状态下特效生命周期的变化规则。

## 2. 核心同步机制：时间单位与信号接口

### 2.1. BPM时间单位体系

游戏中的所有特效时间轴不再使用绝对时间（秒），而是使用基于BPM的相对时间单位。这样设计的核心优势是：当游戏BPM发生变化时（如进入高强度战斗阶段），所有特效的节奏会自动跟随音乐加速或减慢，无需手动调整任何参数。

| 时间单位 | 定义 | 绝对时间（BPM=120时） | 用途 |
| :--- | :--- | :--- | :--- |
| **Tick (十六分音符)** | 1/4 Beat | 0.125 秒 | BGM调度器最小粒度；特效微调精度 |
| **Eighth Note (八分音符)** | 1/2 Beat | 0.25 秒 | 手动施法最小精度；修饰符附着窗口 |
| **Beat (拍/四分音符)** | 1 Beat | 0.5 秒 | 自动施法基本单位；和弦持续计量 |
| **Measure (小节)** | 4 Beats | 2.0 秒 | 自动施法循环单位；和弦进行判定周期 |

> **设计原则：** 所有特效的持续时间均以"Beat"为单位描述。例如，"消散时间 = 0.5 Beat"在BPM=120时为0.25秒，在BPM=140时自动缩短为约0.214秒，始终保持与音乐的比例关系。

### 2.2. BGM信号接口

特效系统通过监听 `BGMManager` 发出的全局节拍信号来驱动动画时序。以下信号由 `BGMManager` 的十六分音符调度器 (`_tick_sixteenth()`) 在正确时间点发射：

| 信号名称 | 触发频率 | 参数 | 特效用途 |
| :--- | :--- | :--- | :--- |
| `sixteenth_note_tick` | 每 Tick | `tick_index` (0-15) | 特效微动画、拖尾波动、修饰符闪烁 |
| `eighth_note_tick` | 每 0.5 Beat | `eighth_index` (0-7) | 手动施法量化点；和弦持续阶段节拍感 |
| `beat_tick` | 每 Beat | `beat_index` (0-3) | 自动施法触发点；法阵/构造体脉冲 |
| `measure_tick` | 每 Measure | `measure_index` | 和弦进行判定；全屏效果触发 |

### 2.3. 特效生命周期的五阶段模型

参照《3D_VFX_Design_Principles_And_Methodology.md》第3.1节的生命周期设计，所有法术特效统一采用五阶段模型：

```
预兆 (Anticipation) → 释放 (Cast) → 持续/飞行 (Sustain/Travel) → 命中/爆发 (Impact) → 消散 (Dissipation)
```

其中，**释放 (Cast)** 阶段是所有时间计算的基准点 `T = 0`，对应 `beat_tick` 或 `eighth_note_tick` 信号触发的精确时刻。

## 3. 节拍量化与视觉补偿机制

由于玩家的手动输入存在人类反应时间误差，特效触发时机可能与完美的节拍点存在微小偏差。"节拍量化"（Beat Quantization）机制负责处理这种偏差，确保视觉上的完美同步。

### 3.1. 输入量化规则

| 施法模式 | 量化精度 | 容差窗口 | 量化逻辑 |
| :--- | :--- | :--- | :--- |
| **自动施法** | `beat_tick` | 无（严格对齐） | 由序列器调度器直接触发，无需量化 |
| **手动施法** | `eighth_note_tick` | ±0.1 Beat | Early输入缓存至下一个Tick触发；Late输入在容差内立即触发并启动视觉补偿 |

**Early输入（提前）处理：** 玩家在节拍点前 0.1 Beat 内按下按键，系统缓存输入，在节拍点精确触发。预兆动画可提前开始，以掩盖等待时间。

**Late输入（滞后）处理：** 玩家在节拍点后 0.1 Beat 内按下按键，系统立即触发，但启动视觉补偿策略（见3.2节）。超过 0.1 Beat 的输入则对齐到下一个八分音符。

### 3.2. 视觉补偿策略

当发生Late输入时，为了让特效看起来仍然是"踩在点上"的，系统采用以下三种策略，根据延迟量自动选择：

**策略一：加速预兆（延迟 < 0.05 Beat）**

压缩预兆阶段的动画时间，使其在下一个关键帧（如释放）赶上标准时间轴。预兆动画以1.5倍速播放，玩家几乎感知不到差异。

**策略二：跳帧快进（0.05 Beat ≤ 延迟 < 0.1 Beat）**

直接跳过特效最初的若干帧，从"应该处于的状态"开始播放。例如，若延迟了0.08 Beat，则预兆动画从其40%进度处开始，确保释放瞬间仍然对齐节拍。

**策略三：弹性拖尾（适用于弹体类特效）**

弹体发射时，拖尾的起始点锚定在玩家核心，弹体头部瞬间到达量化后的位置，形成一种"被拉长后弹射"的视觉错觉。这种方式能够将轻微的延迟转化为一种"爆发感"，反而增强了打击感。

## 4. 基础弹体节奏模型

基础弹体（白键音符 C/D/E/F/G/A/B）是游戏的"原子"单位，其生命周期节奏根据施法模式（自动/手动）有所不同。

### 4.1. 自动施法节奏模型（1 Beat 周期）

自动施法严格对齐 `beat_tick`，每拍发射一个音符。其生命周期节奏如下：

```
[T - 1 Tick]  预兆开始：玩家核心微小收缩，对应音符的色相光晕出现
[T = 0]       释放：beat_tick 触发，弹体生成，枪口闪光（1 Tick 持续）
[T > 0]       飞行：弹体按固定速度飞行，拖尾随 sixteenth_note_tick 微波动
[T = Impact]  命中：命中爆发特效瞬间触发
[T = Impact + 0.25 Beat]  消散完成：残留粒子消散，屏幕空间释放
```

> **关键设计原则：** 自动施法的预兆极短（仅1 Tick = 0.25 Beat），强调"机械性"和"精准性"，与Techno音乐的机械感相契合。消散时间控制在0.25 Beat以内，确保下一拍的弹体不会与上一拍的消散特效产生视觉叠加。

### 4.2. 手动施法节奏模型（强力爆发感）

手动施法对齐到 `eighth_note_tick`，为了强调"强力法术"的质感，其预兆阶段被拉长，释放感更强烈。

```
[T - 0.5 Beat]  预兆开始：玩家按下按键，核心开始强力蓄力，能量向内汇聚
                能量光环收缩，伴随音调上升的音效（由 eighth_note_tick 驱动渐强）
[T = 0]         释放：eighth_note_tick 触发，能量光环猛然扩张
                屏幕产生轻微径向模糊和色散效果（持续 1 Tick）
                弹体以更高速度射出，拖尾更长更亮
[T > 0]         飞行：同自动施法，但弹体视觉参数更强烈
[T = Impact]    命中：命中爆发特效比自动施法强烈1.5倍
[T = Impact + 0.5 Beat]  消散完成：余韵更长，强调"强力一击"的满足感
```

### 4.3. 各音符的节奏参数差异

不同音符的四维参数（DMG/SPD/DUR/SIZE）会影响其节奏模型的具体参数：

| 音符 | 预兆时长 | 飞行时长（估算） | 消散时长 | 节奏感特征 |
| :--- | :--- | :--- | :--- | :--- |
| **C（均衡）** | 1 Tick | 中等 | 0.25 Beat | 标准节奏基准 |
| **D（极速）** | 0.5 Tick | 极短 | 0.25 Beat | 快速干脆，强调速度感 |
| **E（巨型缓行）** | 2 Ticks | 极长 | 0.5 Beat | 缓慢庄重，如重锤落下 |
| **F（超持久）** | 1 Tick | 极长 | 0.5 Beat | 幽灵感，长时间漂浮 |
| **G（高伤快消）** | 0.5 Tick | 短 | 0.125 Beat | 闪电般，转瞬即逝 |
| **A（持久高伤）** | 1.5 Ticks | 长 | 0.375 Beat | 稳健有力 |
| **B（高速高伤）** | 0.5 Tick | 短 | 0.25 Beat | 子弹感，快速有力 |

## 5. 和弦法术节奏模型

和弦法术是游戏的核心输出方式，其生命周期节奏必须与其乐理特性和视觉形态精确匹配。以下模型中，`T = 0` 为法术释放/激活的节拍点（对齐 `beat_tick` 或 `measure_tick`）。

### 5.1. 强化弹体（大三和弦）

大三和弦代表"稳定与和谐"，其节奏感应体现为**饱满、有力、充满信心**。

```
[T - 0.5 Beat]  预兆：金色六边形网格从弹体核心向外扩散，伴随和谐的上升音程
[T = 0]         释放：beat_tick 触发，弹体以1.5倍标准速度射出，枪口产生金色光爆
[T > 0]         飞行：弹体随每个 beat_tick 产生一次金色脉冲发光（强调节拍感）
[T = Impact]    命中：比标准弹体强烈1.5倍的爆炸，金色光屑飞溅
[T = Impact + 0.5 Beat]  消散：金色光斑缓慢消散，余韵充足
```

### 5.2. DOT弹体（小三和弦）

小三和弦代表"忧郁与持续"，其节奏感应体现为**缓慢渗透、持续折磨**。

```
[T - 0.25 Beat]  预兆：蓝色液滴从弹体底部开始滴落聚集
[T = 0]          释放：beat_tick 触发，弹体射出，拖尾是持续滴落的蓝色液滴粒子
[T > 0]          飞行：液滴粒子随 sixteenth_note_tick 规律滴落，形成节拍感
[T = Impact]     命中：蓝色液体溅射，敌人身上出现DOT标记
[DOT持续阶段]    每个 beat_tick，DOT标记跳动一次（视觉上"腐蚀"一次）
[DOT结束]        液体在 0.5 Beat 内蒸发消散
```

### 5.3. 爆炸弹体（增三和弦）

增三和弦代表"膨胀与不稳定"，其节奏感应体现为**急促、紧张、随时爆发**。

```
[T - 0.5 Beat]  预兆：弹体核心以急促的 eighth_note_tick 频率忽明忽暗（不稳定感）
[T = 0]         释放：beat_tick 触发，弹体射出
[T > 0]         飞行：弹体体积随 eighth_note_tick 轻微胀缩（"呼吸"感）
[T = Impact]    命中：剧烈爆炸，冲击波扩散持续 0.5 Beat，地面焦黑纹理出现
[T = Impact + 1 Beat]  消散：余烬粒子随 beat_tick 逐渐熄灭
```

### 5.4. 冲击波（减三和弦）

减三和弦代表"收缩与塌缩"，其节奏感应体现为**蓄力→爆发→内爆**的戏剧性弧线。

```
[T - 1.0 Beat]  预兆：玩家核心周围空间向内扭曲，深紫色能量汇聚（持续整整1 Beat）
[T = 0]         释放：beat_tick 触发，冲击波从核心向外爆发
[T = 0 到 T = 1.5 Beats]  扩散：冲击波以固定速度向外扩散，经过的地面产生"切割"效果
[T = 1.5 Beats] 内爆：冲击波到达最大范围，在 0.5 Beat 内向中心快速塌缩
[T = 2.0 Beats] 消散：内爆完成，产生最终伤害，残留扭曲效果在 0.5 Beat 内消失
```

### 5.5. 法阵/区域（属七和弦）

属七和弦代表"需要解决的持续存在"，其节奏感应体现为**稳定的节拍脉冲，持续施压**。

```
[T - 0.5 Beat]  预兆：地面出现法阵预告线（淡黄色），从中心向外延伸
[T = 0]         激活：measure_tick 或 beat_tick 触发，光柱从天而降，法阵完全展开
[持续阶段]      法阵图案随每个 beat_tick 进行一次明暗闪烁（"心跳"感）
                法阵边缘的上升粒子随 eighth_note_tick 喷发一次
[结束]          持续时间结束，法阵图案在 1 Beat 内碎裂消失（对齐下一个 beat_tick）
```

### 5.6. 天降打击（减七和弦）

减七和弦代表"极度不稳定与毁灭"，其节奏感应体现为**漫长的压迫性预兆，然后瞬间爆发**。

```
[T - 2.0 Beats]  预兆开始：地面出现巨大红色预警圆圈，开始向中心收缩
                 天空变暗，乌云汇聚（随 beat_tick 加剧）
[T - 1.0 Beat]   预兆加强：闪电开始在乌云中闪烁（随 eighth_note_tick 闪烁）
                 预警圆圈收缩速度加快，中心出现向上的吸附粒子
[T = 0]          打击：beat_tick 触发，光柱瞬间落下（单帧）
                 全屏闪白（持续 1 Tick），强烈屏幕震动
[T = 0 到 T = 2 Beats]  消散：碎石和烟尘随 beat_tick 缓慢消散
```

### 5.7. 护盾/治疗法阵（大七和弦）

大七和弦代表"温暖与保护"，其节奏感应体现为**柔和、包裹、持续守护**。

```
[T - 0.5 Beat]  预兆：绿色光点从四面八方向玩家位置汇聚
[T = 0]         激活：beat_tick 触发，护盾瞬间成型，光点融入护盾表面
[持续阶段]      护盾表面蜂巢纹理随 beat_tick 缓慢流动（"呼吸"感）
                护盾受击时，被击中点产生涟漪，随 eighth_note_tick 扩散
[治疗时]        玩家身上有上升的绿色光点，随 beat_tick 喷发一次
[结束]          护盾化为光点飘散，持续 1 Beat
```

### 5.8. 召唤/构造（小七和弦）

小七和弦代表"深沉与构建"，其节奏感应体现为**模块化生长，节拍驱动的脉冲**。

```
[T - 1.0 Beat]  预兆：地面出现构建网格（深蓝色），模块化方块开始出现
[T = 0]         激活：beat_tick 触发，构造体"生长"完成（最后一块模块锁定）
[持续阶段]      构造体核心随每个 beat_tick 发出一次脉冲光（"心跳"感）
                构造体攻击/技能与 beat_tick 同步触发
[结束/死亡]     构造体在 0.5 Beat 内分解为能量方块，方块被吸入地底
```

### 5.9. 蓄力弹体（挂留和弦）

挂留和弦代表"悬而未决"，其节奏感应体现为**持续积累的紧张感，然后突然释放**。

```
[T - 2.0 Beats]  蓄力开始：玩家核心前方出现银白色能量球，开始吸收周围能量
                 能量球随 beat_tick 增大，亮度增加，音效音调上升
[T - 1.0 Beat]   蓄力中期：能量球达到中等大小，空间扭曲效果出现
                 玩家移动速度开始减慢（视觉上的"拉扯感"）
[T - 0.5 Beat]   蓄力完成：能量球达到最大，亮度极高，周围空间剧烈扭曲
[T = 0]          释放：beat_tick 触发，能量球以极高速度射出
                 强烈后坐力视觉效果，玩家核心短暂向后位移
                 弹体拖着长长的彗星尾迹，随 sixteenth_note_tick 波动
[T = Impact]     命中：巨大爆发，余波持续 1 Beat
```

## 6. 黑键修饰符节奏模型

黑键修饰符为下一个法术附加一次性效果，其节奏重点在于"附着"的预示性和"触发"的精准性。

### 6.1. 通用激活-附着流程

```
[玩家放入黑键]    UI立即响应（无延迟），法术槽图标变化
[下一法术预兆开始]  修饰符视觉元素快速生成并附着在弹体上（在预兆阶段的前 0.5 Tick 内完成）
[T = 0]           修饰符效果随法术释放同步激活
```

### 6.2. 各修饰符的触发节奏

| 修饰符 | 附着时机 | 触发时机 | 节奏特征 |
| :--- | :--- | :--- | :--- |
| **穿透 (C#)** | 预兆开始后 0.5 Tick | T=0 释放瞬间 | 激光指示器在预兆期间持续延伸，释放时瞬间消失 |
| **追踪 (D#)** | 预兆开始后 0.5 Tick | 飞行全程 | 准星在飞行中随 eighth_note_tick 旋转，每次改变弹道时闪烁 |
| **分裂 (F#)** | 预兆开始后 1 Tick | T=0 释放瞬间 | 三个内核在预兆期间互相排斥，释放时瞬间分裂 |
| **回响 (G#)** | 预兆开始后 0.5 Tick | T=0 + 0.5 Beat（或1 Beat） | 主弹体释放后，残影弹体在半拍或一拍后生成 |
| **散射 (A#)** | 预兆开始后 1 Tick | T=0 释放瞬间 | 扇形弹道预览在预兆期间展开，释放时同步触发 |

## 7. 节奏型对发射时序的影响

序列器中的节奏型直接改变小节内弹体的发射时序（即 `T = 0` 的定义）。以下时序以一个完整小节（4 Beats）为单位描述。

### 7.1. 连射（均匀八分音符）

每拍发射2个弹体，对齐到 `eighth_note_tick`。

```
发射时序：T = 0, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 3.5 Beats（共8次）
预兆时长：0.5 Tick（极短，强调快速连续感）
弹体大小：-1（视觉上明显变小，形成密集弹幕流）
```

### 7.2. 重击（附点节奏）

附点节奏的发射时序为"长-短-长-短"，强调强拍的力量感。

```
发射时序：T = 0, 0.75, 1.5, 2.25, 3.0, 3.75 Beats
预兆时长：0.5 Beat（比标准更长，强调蓄力感）
弹体飞行速度：-1（视觉上更慢更重）
命中时：击退效果被夸张化，屏幕震动更强烈
```

### 7.3. 闪避射击（切分节奏）

切分节奏在弱拍（八分音符的第二个）发射，制造出"意外感"。

```
发射时序：T = 0.5, 1.5, 2.5, 3.5 Beats（弱拍发射）
发射瞬间：玩家模型向后微小位移（0.1 Beat 内完成），留下短暂残影
残影持续：0.25 Beat 后消失
```

### 7.4. 摇摆弹道（摇摆节奏）

摇摆节奏使弹体以S型/波浪形轨迹飞行，拖尾形成正弦曲线。

```
发射时序：T = 0, 1.0, 2.0, 3.0 Beats（标准四拍）
飞行轨迹：弹体位置随 sixteenth_note_tick 进行正弦波偏移
波动频率：每 0.5 Beat 完成一个完整的正弦周期
拖尾效果：形成平滑的正弦曲线，扫过更大的横向范围
```

### 7.5. 三连发（三连音）

三连音将每拍分为三等份，每次发射3个扇形弹体。

```
发射时序：T = 0, 0.33, 0.67, 1.0, 1.33, 1.67, 2.0, 2.33, 2.67, 3.0, 3.33, 3.67 Beats
每次发射：同时射出3枚呈30度夹角扇形分布的弹体
预兆时长：0.25 Tick（极短，强调快速扇射感）
```

### 7.6. 精准蓄力（休止符）

休止符所在的Beat不发射弹体，但其能量被积蓄到下一个有音符的Beat。

```
休止符阶段：序列器中休止符槽位出现"能量漩涡"动画，随 beat_tick 增强
            每个休止符Beat，漩涡亮度增加 0.5 级（最多叠加4级）
发射时：漩涡能量瞬间被吸入弹体，弹体短暂极大增亮增粗（1 Tick 持续）
        弹体伤害和大小随休止符数量增加（每个+0.5）
```

## 8. 和弦进行组合效果节奏

和弦进行组合效果是高阶操作的奖励，通常以全屏特效的形式出现，需要极强的节奏爆发感。

### 8.1. 触发判定时机

和弦进行效果在**第二个和弦释放的瞬间（T=0，对齐 `measure_tick`）**进行判定。如果满足功能转换条件（D→T/T→D/PD→D），立即触发对应的全屏特效。

### 8.2. D→T（紧张到解决）

```
[T = 0]              触发：全屏闪白（1 Tick），冲击波从玩家中心向全屏爆发
[T = 0 到 T = 1 Beat]  暖色调滤镜维持，所有敌人身上迸发金色光屑
                      如果触发全屏伤害，每个敌人被金色光矛击中（随 beat_tick 依次落下）
[T = 1 到 T = 2 Beats]  暖色调滤镜平滑消散，恢复正常视觉
完整度奖励：3和弦(x1.5)时，光矛数量增加；4和弦(x2.0)时，全屏再次闪白
```

### 8.3. T→D（稳定到紧张）

```
[T = 0]              触发：屏幕四周出现琥珀色能量边框，开始向中心收缩
[T = 0 到 T = 2 Beats]  鱼眼畸变逐渐加剧（随 beat_tick 增强），营造压迫感
                      玩家核心周围能量高速旋转积聚（随 sixteenth_note_tick 加速）
[T = 2 Beats]         达到最大畸变，维持到下一个法术释放
[下一法术释放时]       畸变瞬间消散，释放的法术获得伤害翻倍效果
```

### 8.4. PD→D（准备到紧张）

```
[T = 0]              触发：无数紫色加速线条从屏幕后方向前方掠过（持续 0.5 Beat）
[T = 0 到 T = 1 Beat]  玩家拖尾效果变得更长、更亮（"超空间航行"感）
                      所有弹体的飞行速度视觉上加快（实际速度不变，拖尾更长）
[T = 1 Beat]          效果消散，但冷却缩减效果持续到下一小节结束
```

## 9. 疲劳状态下的生命周期变异

听感疲劳系统（AFI）会动态改变特效的生命周期节奏，作为视觉上的惩罚反馈。这种变异不仅是惩罚，也是给玩家的视觉信号，提示其改变策略。

### 9.1. AFI等级与特效变异规则

| AFI等级 | 阈值 | 特效生命周期变化 | 视觉信号 |
| :--- | :--- | :--- | :--- |
| **无疲劳 (None)** | AFI < 0.2 | 标准生命周期 | 正常特效 |
| **轻度 (Mild)** | 0.2 ≤ AFI < 0.4 | 消散阶段加速50% | 特效余韵变短，画面略显干瘪 |
| **中度 (Moderate)** | 0.4 ≤ AFI < 0.6 | 预兆阶段缩短30%，偶发闪烁 | 预兆不稳定，节奏预期被破坏 |
| **重度 (Severe)** | 0.6 ≤ AFI < 0.8 | 飞行阶段帧率降低（60fps→15fps），消散加速70% | 弹体出现明显"卡顿"和"故障"感 |
| **极度 (Critical)** | AFI ≥ 0.8 | 所有阶段时长随机波动±50%，节拍同步完全失效 | 特效完全脱离节拍，视觉混乱 |

### 9.2. 各疲劳维度对特效的特定影响

| 疲劳维度 | 特效变异 |
| :--- | :--- |
| **音高疲劳 (F_pitch)** | 弹体颜色饱和度降低，趋向灰色 |
| **节奏疲劳 (F_rhythm)** | 发射时序开始偏离节拍，产生轻微随机延迟 |
| **密度疲劳 (F_density)** | 弹体拖尾变短，命中特效缩小，视觉"拥挤感"增加 |
| **留白疲劳 (F_rest)** | 消散特效残留时间延长（本应快速消失的粒子滞留），屏幕空间被占用 |
| **持续压力 (F_sustained)** | 所有特效亮度整体降低，画面变得暗淡 |

### 9.3. 频谱偏移疲劳（Spectrum Corruption）的特效影响

当 `F_spectrum > 0.7` 触发"频谱失调"时：

```
[触发瞬间]  屏幕剧烈扭曲（持续 0.5 Beat），所有正在播放的特效瞬间"冻结"
[持续阶段]  所有特效的节拍同步完全错乱：
            - beat_tick 信号被随机延迟 0~0.5 Beat
            - 特效颜色出现随机色相偏移（±30度）
            - 粒子运动方向随机偏转
[恢复阶段]  玩家返回全频相位后，F_spectrum 降至 0.3 以下时，
            特效节拍同步在 2 Beats 内逐渐恢复正常（不是瞬间恢复）
```

## 10. 实现指南

### 10.1. 特效时序控制器（VFXTimingController）

建议在 `VFXManager` 中实现一个 `VFXTimingController` 组件，负责：

1. 监听 `BGMManager` 的所有节拍信号。
2. 维护一个"特效时序队列"，存储所有待触发的特效及其目标触发时间。
3. 在每个 `sixteenth_note_tick` 检查队列，触发到期的特效。
4. 根据当前 AFI 等级，动态调整特效的生命周期参数。

### 10.2. 特效参数结构

每个特效实例应包含以下节奏相关参数：

```gdscript
class VFXBeatParams:
    var anticipation_beats: float  # 预兆时长（以Beat为单位）
    var cast_beat_align: String    # 对齐信号类型（"beat", "eighth", "measure"）
    var sustain_beats: float       # 持续时长（0表示无持续阶段）
    var dissipation_beats: float   # 消散时长
    var beat_pulse: bool           # 是否在每个beat_tick产生脉冲效果
    var tick_pulse: bool           # 是否在每个sixteenth_note_tick产生微动效
    var fatigue_scale: float       # 疲劳缩放系数（由AFI动态更新）
```

### 10.3. 量化补偿实现

```gdscript
func quantize_and_trigger(vfx_id: String, input_time: float, target_beat_time: float):
    var delay = input_time - target_beat_time
    if delay < 0:  # Early输入
        # 缓存，在 target_beat_time 触发
        schedule_vfx(vfx_id, target_beat_time)
    elif delay < 0.05 * beat_duration:  # 轻微Late：加速预兆
        trigger_vfx_with_accelerated_anticipation(vfx_id, delay)
    elif delay < 0.1 * beat_duration:  # 较多Late：跳帧
        trigger_vfx_with_frame_skip(vfx_id, delay)
    else:  # 超出容差：对齐到下一个eighth_note
        schedule_vfx(vfx_id, next_eighth_note_time)
```

本文档建立了《Project Harmony》法术特效的完整节拍同步模型，将特效的每一个生命周期阶段精确锚定到BGM的时间网格上。通过统一的BPM时间单位体系、完善的节拍量化机制、以及与疲劳系统的深度整合，本模型确保了游戏在视觉表现上能够实现真正的"节奏同步"。
