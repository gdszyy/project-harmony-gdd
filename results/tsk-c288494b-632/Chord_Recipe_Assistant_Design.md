## 1. 问题背景与设计目标

### 1.1. 问题背景

《Project Harmony》以音乐理论为核心玩法，其和弦炼成系统是整个战斗循环的关键环节。然而，根据《教学设计评估报告》[1] 的深度分析，随着游戏进程的推进，玩家需要记忆的和弦配方数量急剧增加——`MusicData.gd` 中定义了包括9种基础和弦与8种扩展和弦在内的共17种配方 [3]，加之每种配方可以任意音符为根音，实际的组合数量更为庞大。

> "对于完全没有乐理基础的玩家，在第四章以后可能会面临较大的认知负担。" — 教学设计评估报告，第2.5节 [1]

当前的和弦炼成台（`chord_alchemy_panel_v3.gd`）[4] 依赖玩家的自主记忆与反复试错，缺乏主动的引导机制。这使得"和弦炼成"这一核心创造行为，对于非音乐专业玩家而言，容易从"有趣的探索"退化为"令人沮丧的记忆负担"，直接影响游戏的可及性与长期留存率。

### 1.2. 设计目标

本次设计旨在为和弦炼成台引入一套**配方辅助与智能预测系统**，以实现以下核心目标：

| 设计目标 | 具体表现 |
| :--- | :--- |
| **降低记忆负担** | 建立自动化图鉴，记录已发现的配方，使玩家无需强行记忆 |
| **引导主动发现** | 通过智能预测，将"盲目试错"转变为"有指导的探索" |
| **强化核心循环** | 使和弦的"发现"和"创造"本身成为有趣、有回报的玩法 |
| **无缝整合体验** | 与现有"一体化编曲台"[2]的设计语言和交互逻辑保持一致 |

### 2.2. 现有炼成台工作流分析

现有的炼成台（`chord_alchemy_panel_v3.gd`）[4] 提供了6个原材料槽，玩家通过拖拽音符放入槽位，系统会实时匹配 `CHORD_PATTERNS` 字典中的配方。其核心识别逻辑是：将槽内所有音符转换为半音值，以每个音符为潜在根音，计算音程模式，并在配方字典中查找匹配项。

**现有系统的核心局限性**在于：它只能在玩家已经放入足够音符（≥3个）后才给出反馈，而在此之前，玩家完全处于"信息真空"状态，不知道自己正在朝哪个方向努力。这正是本次设计需要解决的核心问题。

## 3. 配方图鉴系统设计 (Chord Codex)

配方图鉴（Chord Codex）是一个**自动记录玩家已发现和弦配方**的持久化系统，作为"一体化编曲台"右侧面板的新增标签页存在。

### 3.1. 核心机制

**自动记录与解锁。** 当玩家在炼成台中首次成功合成某种类型的和弦时，该和弦的通用配方将被自动解锁并添加到图鉴中。例如，首次炼成"C大三和弦"后，"大三和弦"这一配方类型即被解锁，其音程规则（根音+4半音+7半音）也随之可见。与此同时，"C"这一根音版本会在该配方的"根音发现矩阵"中被点亮。

**分级解锁与迷雾系统。** 未被发现的和弦配方将以"未知的配方"形式显示，图标被替换为问号，名称被替换为"??? 和弦"。这一设计保留了探索的神秘感，同时也向玩家暗示"还有更多待发现的内容"，激发其探索欲望。扩展和弦（需要传说级升级解锁）在未解锁时会额外显示"🔒 需要传说升级"的提示，而非完全隐藏，以避免玩家困惑。

**持久化存储。** 图鉴数据将被存储在玩家的存档文件中，跨局保留。这意味着玩家在多次游玩中积累的知识会被永久记录，形成一种"元进度"感，增强游戏的长期吸引力。

### 3.2. 分类体系

图鉴内的和弦将按以下三个层级进行分类，方便玩家系统性地查阅：

| 分类 | 包含和弦 | 音符数量 |
| :--- | :--- | :---: |
| **三音和弦** | 大三、小三、增三、减三、挂留 | 3 |
| **七和弦** | 属七、减七、大七、小七、半减七、增大七 | 4 |
| **扩展和弦** ★ | 属九、大九、减九、属十一、属十三、减十三 | 5–7 |

### 3.3. 图鉴条目详情

每个图鉴条目的详情页将展示以下信息：

**和弦基本信息区（顶部）。** 显示和弦名称、法术形态图标（与现有视觉编码系统 [2] 保持一致）、不和谐度等级（以1–5颗音符符号表示，对应 `CHORD_DISSONANCE` 数据 [3]）以及伤害倍率。

**音程结构可视化区（中部）。** 以一个小型的"半音键盘"示意图展示该和弦的音程结构。键盘上，根音位置标注"R"，其他构成音位置以对应颜色高亮，直观地展示半音间隔关系。例如，大三和弦（0, 4, 7）会在第1、第5、第8个半音位置高亮。

**效果描述区（中部）。** 显示该和弦对应的法术形态名称及其效果描述，内容来源于 `_CHORD_PATTERNS_LEGACY` 字典中的 `desc` 字段 [4]。

**根音发现矩阵（底部）。** 由12个方块组成的矩阵，分别对应12个半音（C, C#, D, D#, E, F, F#, G, G#, A, A#, B）。玩家已成功炼成过的根音版本将被点亮（使用对应音符的颜色编码 [2]），未发现的则显示为灰色。这一设计为收集型玩家提供了额外的完成度目标。

## 4. 智能预测功能设计 (Intelligent Prediction)

智能预测功能直接集成在现有的和弦炼成台中，在玩家放置音符时提供**实时的合成可能性提示**。

### 4.1. 核心机制

**实时分析触发。** 每当炼成槽的内容发生变化（音符被放入或移出），系统会立即触发一次预测分析。分析的输入是当前槽内所有音符的半音值集合，输出是一个"可能构成的和弦"列表。

**预测算法逻辑。** 系统遍历图鉴中所有已解锁的和弦配方，对每种配方，以12个半音为根音逐一检验：当前槽内的音符集合是否是该配方所需音符集合的子集。若是，则该配方被纳入预测结果，并计算出"还需要哪些音符"。

**库存可用性分析。** 对于每个预测结果中"还需要的音符"，系统会与玩家当前的音符库存（`NoteInventory`）进行比对，判断这些音符是否有库存。

**排序规则。** 预测结果将按以下优先级排序，确保最有价值的提示最先显示：

1. **立即可完成（库存充足）：** 所有"还需音符"均有库存的配方，排在最前。
2. **部分可完成（库存不足）：** 部分"还需音符"有库存的配方，按缺少音符数量升序排列。
3. **暂不可完成（库存全缺）：** 所有"还需音符"均无库存的配方，排在最后。

### 4.2. 图鉴联动高亮

当预测分析完成后，图鉴面板中符合条件的配方条目将以**发光边框**高亮显示，颜色根据可完成度分级：

| 高亮颜色 | 含义 |
| :--- | :--- |
| **谐振青** (`#00FFD4`) | 立即可完成，库存中有所有所需音符 |
| **烈日橙** (`#FF8800`) | 部分可完成，还缺少少量音符 |
| **晶体白** (`#EAE6FF`, 低透明度) | 当前放入的音符包含在此配方中，但缺少较多音符 |

### 4.3. 详情页增强

当玩家点击一个高亮的预测配方时，其详情页将在原有内容基础上增加一个**"预测辅助区"**：

**当前已有音符（绿色高亮）。** 在音程结构可视化图上，当前槽内已有的音符位置会以更亮的颜色高亮，并附加一个"✓"标记。

**还需音符（带库存状态）。** 在音程结构图下方，以列表形式显示"还需要的音符"。每个音符旁边会显示其库存数量。库存充足的音符名称使用对应的颜色编码 [2] 高亮，库存为零的则显示为灰色并附注"（库存不足）"。

**一键填充按钮（条件激活）。** 当所有"还需音符"均有库存时，详情页底部会出现一个"自动填充剩余音符"按钮（使用谐振青色高亮）。点击后，系统会自动将所需音符从库存中拖入炼成槽的空位，并触发相应的视觉与听觉反馈。这一功能大幅降低了熟悉配方后的操作成本。

## 5. 完整交互流程场景化描述

以下通过一个完整的场景，展示两个功能协同工作的用户体验。

**场景：玩家首次尝试炼成大七和弦（护盾/治疗法阵）**

**步骤一（打开图鉴）。** 玩家在战斗间隙打开一体化编曲台，切换到图鉴标签页。他看到"大七和弦"条目（假设之前未发现），显示为"??? 和弦"，但旁边有一个隐约的盾牌轮廓图标，激起了他的好奇心。

**步骤二（放入第一个音符）。** 玩家从库存中拖入一个"C"音符到炼成槽。此时，图鉴中所有包含C音的和弦配方（包括那个神秘的"??? 和弦"）都被橙色边框高亮。玩家注意到那个盾牌图标的"??? 和弦"也被高亮了。

**步骤三（查看预测详情）。** 玩家点击那个高亮的"??? 和弦"。由于该和弦尚未被发现，详情页只显示"还需音符：E, G, B（均有库存）"，以及一个"自动填充"按钮。法术效果仍然是隐藏的"???"。

**步骤四（使用一键填充）。** 玩家点击"自动填充"按钮。系统自动将E、G、B三个音符填入炼成槽的空位，炼成按钮立刻高亮。

**步骤五（炼成与发现）。** 玩家点击"炼成"按钮。一段悦耳的大七和弦琶音响起，炼成成功。此时，一个特殊的"首次发现"动画触发：图鉴中那个"??? 和弦"的迷雾消散，"大七和弦"的名称、盾牌图标和完整效果描述（"护盾/治疗法阵：恢复生命值"）以动画形式逐渐显现。根音发现矩阵中，"C"的方块被点亮。

**步骤六（知识积累）。** 玩家下次打开图鉴时，"大七和弦"已经是一个完整的、可查阅的条目。他已经知道了这个配方的规则，下次可以直接放入所需音符，无需再依赖预测功能的引导。

## 6. 与现有系统的整合方案

### 6.1. 数据层改动

**`NoteInventory.gd`（或全局数据管理单例）** 需要增加以下数据结构：

```gdscript
# 已解锁的和弦配方图鉴
# key: 和弦类型枚举值 (ChordType), value: { "unlocked": bool, "discovered_roots": Array[int] }
var chord_codex: Dictionary = {}

# 初始化图鉴（所有和弦默认未解锁）
func _init_chord_codex() -> void:
    for chord_type in MusicData.ChordType.values():
        chord_codex[chord_type] = {
            "unlocked": false,
            "discovered_roots": []
        }

# 解锁一个和弦配方（首次发现时调用）
func unlock_chord_recipe(chord_type: MusicData.ChordType, root_semitone: int) -> bool:
    if not chord_codex.has(chord_type):
        return false
    var was_new_type = not chord_codex[chord_type]["unlocked"]
    chord_codex[chord_type]["unlocked"] = true
    if not chord_codex[chord_type]["discovered_roots"].has(root_semitone):
        chord_codex[chord_type]["discovered_roots"].append(root_semitone)
    return was_new_type  # 返回是否是首次发现该类型
```

### 6.2. 炼成台改动

**`chord_alchemy_panel_v3.gd`** [4] 需要进行以下改动：

在 `_execute_alchemy()` 函数中，炼成成功后，调用 `NoteInventory.unlock_chord_recipe()` 记录发现，并根据返回值决定是否触发"首次发现"动画。

增加一个新函数 `_get_predictions()` 用于预测分析，该函数在 `_update_preview()` 被调用时同步触发，并通过信号将预测结果传递给图鉴面板。

### 6.3. UI层改动

**`IntegratedComposer.tscn`** 场景需要进行以下改动：

将原有的法术书列表（`SpellbookPanel`）包装在一个 `TabContainer` 中，增加"已装备"和"图鉴"两个标签页。

## 7. 视觉与听觉反馈规范

本设计严格遵循现有的"抽象矢量主义"美术风格 [2]，所有新增视觉元素均使用已定义的颜色编码系统。

| 交互事件 | 视觉反馈 | 听觉反馈 |
| :--- | :--- | :--- |
| 放入音符，触发预测 | 图鉴面板相关条目出现发光边框（0.3s淡入） | 一个轻柔的"叮"声，音高对应放入的音符 |
| 预测到可立即完成的配方 | 青色边框 + 轻微脉冲动画 | 一个上行的两音短旋律 |
| 悬停在高亮的预测配方上 | 边框亮度提升，出现工具提示 | 无 |
| 点击"自动填充"按钮 | 音符图标以流动轨迹飞入炼成槽 | 一段快速的音阶上行音效 |
| 首次发现新和弦 | 全屏柔光闪烁（0.5s），图鉴条目以动画展开 | 完整的和弦琶音 + 发现音效 |
| 图鉴条目从"未知"变为"已知" | 问号图标以旋转动画替换为真实图标 | 一个"解锁"音效 |

## 8. 实现优先级建议

考虑到开发资源，建议按以下优先级分阶段实现：

**P0（核心功能，必须实现）：** 配方图鉴的数据层（`chord_codex` 数据结构）、炼成成功后的自动记录、图鉴面板的基础浏览功能（列表+详情）。

**P1（高价值功能，强烈建议实现）：** 智能预测的实时分析与图鉴高亮、"还需音符"的库存联动显示、预测结果的排序逻辑。

**P2（增强功能，条件允许时实现）：** "一键填充"按钮、首次发现的特殊动画、根音发现矩阵的视觉化。
